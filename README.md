# StudioLite

Лёгкая десктоп-панель для Android-проекта: git, выбор устройства, сборка и запуск — без тяжёлой IDE.

StudioLite не заменяет редактор кода. Он закрывает рутину, ради которой обычно приходится держать открытой Android Studio: посмотреть, что изменилось в git, выбрать телефон или эмулятор, собрать и запустить приложение, забрать готовый APK.

## Возможности

**Проект и файлы**
- Дерево файлов с ленивой загрузкой и цветами по git-статусу: изменённые, новые, удалённые, конфликтные.
- Просмотр файлов во вкладках: подсветка синтаксиса, номера строк. Только чтение.
- Контекстное меню: открыть в системе, показать в проводнике, скопировать путь.

**Git**
- Граф коммитов всех веток с бейджами веток, тегов и HEAD.
- Текущая ветка в тулбаре.

**Устройства**
- Подключённые телефоны (USB и Wi‑Fi через adb) и запущенные эмуляторы.
- Выключенные эмуляторы запускаются прямо из списка и продолжают работать после закрытия StudioLite.

**Сборка**
- **Run** — установить и запустить приложение на выбранном устройстве; выключенный эмулятор сначала будет запущен.
- **Build** — собрать debug-сборку.
- **Сборка APK** — debug APK или release APK вместе с AAB; готовые файлы складываются в `dist/<вариант>` в корне проекта.
- **Clean** и остановка Gradle daemon.
- Вывод Gradle в реальном времени с подсветкой ошибок и предупреждений; **Stop** прерывает задачу целиком.

**Чат**
- Чаты с консольной программой-агентом, установленной на компьютере: она работает в папке открытого проекта.
- Несколько чатов во вкладках, история сохраняется по проектам.
- Выбор модели, уровня усилий и того, что чату разрешено делать в проекте.
- К сообщению можно приложить изображения: вставить из буфера, выбрать файл или перетащить.
- Какая программа используется, задаётся в настройках приложения на вашем компьютере.

## Что нужно для работы

- **Android SDK** с `platform-tools` (adb); для эмуляторов — пакет `emulator`. SDK ищется в `ANDROID_HOME`, `ANDROID_SDK_ROOT`, `sdk.dir` из `local.properties` проекта и в стандартных папках.
- **git** в `PATH`.
- **JDK** для Gradle. Если `JAVA_HOME` не задан и `java` не найдена, используется JDK из установленной Android Studio.
- Проект с Gradle wrapper (`gradlew`). Сборка и запуск рассчитаны на модуль `app`.

## Запуск из исходников

Понадобятся [Node.js](https://nodejs.org/), [Rust](https://www.rust-lang.org/tools/install) и [системные зависимости Tauri](https://tauri.app/start/prerequisites/) для вашей ОС.

```sh
npm install
npm run tauri dev
```

Собрать установочный пакет:

```sh
npm run tauri build
```

## Проверки

```sh
npm run build                     # проверка типов и сборка интерфейса
npm test                          # тесты интерфейса
cd src-tauri && cargo test        # тесты backend
```

## Платформы

Код написан для macOS, Windows и Linux, но разрабатывался и проверялся только на macOS. На Windows и Linux возможны недочёты — сообщения о них приветствуются.

## Как устроено

- **Интерфейс** — Vue 3, TypeScript, Pinia (`src/`).
- **Backend** — Rust на Tauri 2 (`src-tauri/`).
- Внешние программы (git, Gradle, adb, emulator) запускаются только из Rust с фиксированным набором аргументов; интерфейс не может выполнить произвольную команду.
- Данные обновляются по фокусу окна, после задач и по кнопке — фоновых опросов нет.

## Ограничения

- Редактирования кода нет: файлы открываются только для просмотра.
- Модуль (`app`) и варианты сборки (`debug` / `release`) пока не настраиваются из интерфейса.
- Release-сборка подписывается только если подпись настроена в самом проекте; StudioLite ничего не подписывает сам.
- Logcat и просмотр diff пока не реализованы.
